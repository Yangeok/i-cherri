# Feature Specification: iOS 화면 꺼짐 자동 백업

**Feature Branch**: `002-background-auto-backup`

**Created**: 2026-06-12

**Status**: Draft

**Input**: User description: "iPhone 화면이 꺼진 상태에서도 계속 진행되거나 앱 재실행 후 이어질 수 있는 iOS 자동 사진/영상 백업 기능을 정의한다. 이 기능은 OS가 관리하는 백그라운드 실행 모델을 사용하고, macOS receiver는 재시도·중복 요청·부분 업로드 복구에 안전한 resumable 프로토콜을 제공해야 한다."

## Clarifications

### Session 2026-06-12

- Q: Mac receiver가 잠자거나 네트워크에서 사라져 미도달 상태가 되면 현재 run을 어떻게 취급하는가? → A: 자동 일시정지하고 상태를 보존한 뒤, 다음 조건 충족 시 재개
- Q: iOS 임시 업로드 파일의 최대 디스크 사용량은 얼마인가? → A: 고정 2GB 상한
- Q: 자동 백업 시작 조건은 무엇인가? → A: 충전 중이 아니어도 되며, 배터리 20% 이상이고 Wi-Fi가 켜져 있을 때만 시작하고 저전력 모드는 막지 않는다
- Q: 기기가 과열되면 자동 백업 run을 어떻게 처리하는가? → A: 과열 시 현재 run을 일시 중단하고 상태를 보존하며, 온도가 내려가면 재평가 후 다시 시작한다
- Q: 자동 백업 run 안에서 실패한 항목을 즉시 재시도하는가? → A: 같은 run 안에서는 즉시 재시도하지 않고 실패로 남긴 뒤 다음 자동 백업 run에서 다시 시도한다
- Q: 자동 백업 run의 범위는 무엇인가? → A: 라이브러리 전체가 아니라 이번 실행에서 실제로 평가하고 처리하는 대상 집합이다
- Q: 사용자에게 로그를 직접 보여주는가? → A: 사용자용 로그 뷰어는 만들지 않고 상태 요약만 보여주며, 로그는 내부 진단용으로만 유지한다
- Q: 자동 백업 도중 백업 대상 Mac이 다른 Mac으로 바뀌면 미완료 run을 어떻게 처리하는가? → A: 기존 run은 이전 Mac 기준으로 보존하고, 새 Mac에서는 새 run을 시작하며 cross-Mac handoff는 허용하지 않는다
- Q: 실패 항목과 미완료 run 기록은 얼마나 오래 보존하는가? → A: 실패 항목은 성공할 때까지 다음 run에서 계속 재평가하고, 미완료 run 기록은 7일 동안 보존한다

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 조건 충족 시 자동 백업 시작 (Priority: P1)

사용자는 iPhone의 배터리 잔량이 20% 이상이고 Wi-Fi가 켜져 있으며 허용된 네트워크와 전원 조건을 만족하면 직접 앱을 열어 두지 않아도 사진과 영상 백업이 자동으로 시작되기를 원한다.

**Why this priority**: 사용자가 수동으로 앱을 열고 기다려야 하는 불편을 없애는 것이 이 기능의 핵심 가치다.

**Independent Test**: 자동 백업이 활성화된 상태에서 시작 조건을 만족시키면, 사용자가 앱을 직접 조작하지 않아도 새로 추가된 사진과 영상이 백업 대상으로 예약되고 백업이 시작되면 이 스토리는 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 자동 백업이 활성화되어 있고 배터리 잔량이 20% 이상이며 Wi-Fi가 켜져 있고 허용된 네트워크에 연결되어 있을 때, **When** 백업 대상 사진 또는 영상이 존재하면, **Then** 시스템은 자동 백업 run을 생성하고 사용자 개입 없이 백업을 시작해야 한다.
2. **Given** 자동 백업이 활성화되어 있지만 시작 조건이 충족되지 않을 때, **When** 시스템이 자동 백업 시점을 평가하면, **Then** 백업은 시작되지 않아야 하고 보류 이유가 기록되어야 한다.

---

### User Story 2 - 화면이 꺼지거나 앱이 중단되어도 이어서 백업 (Priority: P2)

사용자는 백업 중 화면이 꺼지거나 앱이 일시 중단되더라도 이미 시작된 백업이 최대한 이어지고, 중간에 끊기더라도 다시 열었을 때 복구되기를 원한다.

**Why this priority**: 자동 시작만 되고 이어서 진행되지 않으면 실사용 가치가 크게 떨어진다.

**Independent Test**: 진행 중인 백업 도중 화면을 끄거나 앱을 종료한 뒤 다시 조건을 만족시키면, 중복 없이 미완료 작업이 이어서 처리되면 이 스토리는 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 자동 백업 run이 일부 파일을 처리한 상태일 때, **When** 앱이 중단되거나 다시 실행되면, **Then** 시스템은 미완료 항목만 복구하여 이어서 처리해야 한다.
2. **Given** 동일한 자동 백업 run이 재개되는 상황일 때, **When** 이미 처리된 항목과 미처리 항목이 함께 존재하면, **Then** 시스템은 이미 완료된 항목은 다시 업로드하지 않고 미처리 항목만 이어서 처리해야 한다.

---

### User Story 3 - 자동 백업 상태와 예외를 이해 가능하게 확인 (Priority: P3)

사용자는 자동 백업이 왜 시작되지 않았는지, 왜 멈췄는지, 무엇이 완료되었는지 앱에서 이해할 수 있기를 원한다.

**Why this priority**: 자동화 기능은 보이지 않는 동안 동작하므로, 상태 설명과 실패 이유가 없으면 신뢰하기 어렵다.

**Independent Test**: 자동 백업이 성공, 대기, 일시정지, 일부 실패 상태에 들어갈 때 각 상태와 이유가 일관되게 표시되면 이 스토리는 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 자동 백업이 예약, 준비, 업로드, 일시정지, 완료, 일부 실패 상태 중 하나에 있을 때, **When** 사용자가 앱을 열면, **Then** 현재 상태와 최근 결과를 이해할 수 있는 요약이 표시되어야 한다.
2. **Given** 자동 백업이 열, 전원, 네트워크, receiver 부재 등의 이유로 멈춘 상태일 때, **When** 사용자가 상태를 확인하면, **Then** 백업이 멈춘 이유와 재개 조건이 표시되어야 한다.

---

### Edge Cases

- 자동 백업이 시작되기 직전에 2GB 임시 파일 상한을 초과하는 준비 파일이 필요한 경우, 현재 run은 시작되지 않거나 보류되어야 하며 사용자에게 이유가 표시되어야 한다.
- 백업 도중 Mac receiver가 잠자거나 네트워크에서 사라지면 현재 run은 자동 일시정지 상태로 전환되고, 상태를 보존한 채 다음 조건 충족 시 재개되어야 한다.
- 자동 백업 도중 백업 대상 Mac이 다른 Mac으로 바뀌면, 이전 Mac에서 진행 중이던 미완료 run은 그 Mac에 귀속된 상태로만 보존되고 새 Mac이 이를 이어받지 않아야 한다.
- 동일한 사진 또는 영상이 중복 요청, 중복 재개, 앱 재실행 후 재평가를 거쳐 여러 번 제출되더라도 최종 저장 결과는 한 번만 반영되어야 한다.
- 진행 중인 백업 중 기기가 과열 상태에 진입하면 이미 준비된 작업과 미완료 작업은 보존되어야 하며, 온도 정상화 후 이어서 처리되어야 한다.
- 백업 중 일부 파일만 성공하고 일부는 실패한 경우, 다음 자동 백업에서 어떤 항목만 재시도되는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 iOS 자동 백업 기능을 켜고 끌 수 있게 해야 한다.
- **FR-002**: 시스템은 자동 백업 시작 조건을 충전 상태, 허용된 네트워크 유형, 저전력 모드 여부, 기기 열 상태를 기준으로 평가해야 한다.
- **FR-002a**: 시스템은 충전 중이 아니어도 자동 백업을 시작할 수 있어야 하며, 배터리 잔량이 20% 미만이면 자동 백업을 시작하지 말아야 한다.
- **FR-002b**: 시스템은 Wi-Fi가 켜져 있을 때만 자동 백업을 시작할 수 있어야 한다.
- **FR-002c**: 시스템은 저전력 모드가 켜져 있어도 다른 시작 조건이 충족되면 자동 백업을 시작할 수 있어야 한다.
- **FR-003**: 시스템은 시작 조건이 충족되지 않으면 자동 백업을 시작하지 말아야 하며, 보류 이유를 사용자에게 설명 가능하도록 기록해야 한다.
- **FR-004**: 시스템은 자동 백업 run의 식별자, 대상 receiver, 진행 상태, 항목별 상태, 재시도 상태, 마지막 평가 시각을 영속 저장해야 한다.
- **FR-004a**: 자동 백업 run은 라이브러리 전체가 아니라, 해당 실행에서 실제로 평가 및 처리 대상으로 선정된 항목 집합만을 포함해야 한다.
- **FR-005**: 시스템은 앱이 중단되거나 다시 실행된 후에도 미완료 자동 백업 run을 복구할 수 있어야 한다.
- **FR-006**: 시스템은 자동 백업 대상 사진 및 영상의 임시 준비 파일을 관리해야 하며, 임시 준비 파일 총 사용량이 2GB 고정 상한을 초과하지 않도록 보장해야 한다.
- **FR-007**: 시스템은 임시 준비 파일이 더 이상 필요하지 않을 때 정리해야 하며, 실패 또는 중단 상황에서도 정리 규칙이 일관되어야 한다.
- **FR-007a**: 시스템은 새로운 임시 준비 파일 생성으로 2GB 상한을 초과하게 되는 경우, 해당 항목 또는 run을 보류하고 사용자가 이해할 수 있는 사유를 남겨야 한다.
- **FR-008**: 시스템은 현재의 중복 판정 흐름을 유지하면서도, 자동 백업 재개 과정에서 이미 완료된 항목을 다시 업로드하지 않아야 한다.
- **FR-009**: 시스템은 자동 백업 중 일부 항목만 성공한 경우에도 성공 항목과 미완료 항목을 구분해 다음 run에서 이어서 처리해야 한다.
- **FR-010**: 시스템은 항목별 및 run별 재시도 규칙을 적용해야 하며, 재시도 횟수 초과 또는 만료 시 실패 상태를 명확히 남겨야 한다.
- **FR-010a**: 같은 run 안에서 실패한 항목은 즉시 재시도하지 말아야 하며, 실패 항목으로 기록한 뒤 다음 자동 백업 run에서 다시 평가해야 한다.
- **FR-010b**: 시스템은 실패 항목을 성공할 때까지 이후 자동 백업 run에서 계속 재평가해야 한다.
- **FR-010c**: 시스템은 미완료 자동 백업 run 기록을 7일 동안 보존해야 하며, 보존 기간이 지난 run 기록은 정리할 수 있어야 한다.
- **FR-011**: 시스템은 자동 백업이 열, 전원, 네트워크, receiver 부재 등의 이유로 일시정지될 수 있어야 하며, 특히 receiver 미도달 시 현재 run을 자동 일시정지 상태로 보존한 뒤 다음 조건 충족 시 재개해야 한다.
- **FR-011a**: 시스템은 기기 열 상태가 과열 단계에 들어가면 현재 run을 일시 중단하고 상태를 보존해야 하며, 온도 정상화 후 재개 가능 여부를 다시 평가해야 한다.
- **FR-012**: 시스템은 동일한 백업 항목이 중복 요청되거나 재연결 후 다시 제출되더라도 receiver 측 최종 결과가 한 번만 반영되도록 보장해야 한다.
- **FR-013**: 시스템은 macOS receiver가 부분 업로드 진행률을 기억하고, 동일 항목 재시도 시 이어서 받을 수 있어야 한다.
- **FR-014**: 시스템은 paired device 정리 이후에도 물리 백업 파일을 삭제하지 말아야 하며, 이후 중복 판정 정확성을 복구할 수 있어야 한다.
- **FR-015**: 시스템은 자동 백업 상태를 예약됨, 준비 중, 업로드 중, 일시정지됨, receiver 대기 중, 완료, 일부 실패로 구분해 사용자에게 표시해야 한다.
- **FR-015a**: 시스템은 사용자에게 현재 상태, 최근 결과, 보류 또는 일시정지 이유, 마지막 성공 시각, 다음 재평가 또는 재개 대기 상태를 이해할 수 있는 수준으로만 표시해야 하며, 상세 로그 뷰어는 제공하지 않는다.
- **FR-016**: 시스템은 자동 백업이 시작, 보류, 재개, 완료, 실패될 때 진단에 필요한 이벤트를 내부 로그와 영속 상태에 남겨야 한다.
- **FR-017**: 시스템은 Mac receiver가 변경되거나 더 이상 도달 불가능할 때, 기존 자동 백업 run이 자동 일시정지되어 보존되었는지, 재개 조건이 무엇인지 사용자에게 명확히 표시해야 한다.
- **FR-017a**: 시스템은 자동 백업 도중 백업 대상 Mac이 다른 Mac으로 바뀌면, 이전 Mac에 귀속된 미완료 run과 receiver session을 새 Mac으로 handoff하지 말아야 하며, 새 Mac에서는 새 run을 시작해야 한다.
- **FR-018**: 시스템은 셀룰러 네트워크를 기본 자동 백업 경로로 사용하지 말아야 한다.
- **FR-019**: 시스템은 원본 사진과 영상을 iPhone Photos에서 삭제하거나 수정하지 말아야 한다.

### Key Entities *(include if feature involves data)*

- **자동 백업 정책**: 자동 백업 가능 여부를 판단하는 규칙 집합으로, 충전 상태, 허용 네트워크, 저전력 모드, 열 상태, 2GB 임시 저장 공간 한도를 포함한다.
- **자동 백업 run**: 한 번의 자동 백업 실행 단위로, 해당 실행에서 실제로 평가 및 처리 대상으로 선정된 항목 집합을 포함하며, run 식별자, 선택된 receiver, 현재 상태, 시작/중단/일시정지 사유, 생성 시각, 마지막 갱신 시각을 가진다.
- **자동 백업 항목**: run 안에서 처리되는 개별 사진 또는 영상 단위로, 항목 식별자, 준비 상태, 업로드 상태, 재시도 상태, 최종 결과를 가진다.
- **실패 항목 보존 규칙**: 이전 run에서 실패한 자동 백업 항목을 다음 run에서 다시 평가하기 위한 규칙으로, 성공 시까지 재평가 대상에 포함되는지 여부와 마지막 실패 시각을 가진다.
- **임시 준비 파일**: 자동 백업을 위해 생성된 중간 파일로, 원본 참조, 현재 용도, 생성 시각, 만료 시각, 정리 가능 여부, 누적 사용량 계산 대상 여부를 가진다.
- **receiver 세션**: macOS receiver가 특정 항목 업로드 진행률을 추적하는 단위로, 대상 항목, 현재까지 받은 양, 만료 시각, 재개 가능 상태를 가진다.
- **백업 이벤트 기록**: 자동 백업 시작, 보류, 재시도, 재개, 완료, 실패 사유를 남기는 진단용 기록이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 시작 조건이 충족된 자동 백업 대상 run의 90% 이상이 사용자 수동 개입 없이 백업을 시작한다.
- **SC-001a**: 배터리 잔량 20% 이상이며 Wi-Fi가 켜진 조건에서 자동 백업 대상 run의 90% 이상이 사용자 수동 개입 없이 백업을 시작한다.
- **SC-002**: 화면 꺼짐, 앱 중단, 앱 재실행 이후 복구 대상이 된 자동 백업 run의 95% 이상이 이미 완료된 항목을 중복 업로드하지 않고 이어서 처리된다.
- **SC-003**: 자동 백업 상태 확인 화면에서 사용자는 30초 이내에 현재 상태, 마지막 결과, 보류 또는 실패 이유를 이해할 수 있어야 한다.
- **SC-004**: 자동 백업 중 일부 실패가 발생한 run의 100%에서 성공 항목과 재시도 대상 항목이 구분되어 다음 실행 시 재사용된다.
- **SC-004a**: 실패 항목의 95% 이상이 7일 보존 기간 안의 이후 자동 백업 run에서 다시 평가 대상에 포함된다.
- **SC-005**: 중복 요청, 재연결, 부분 업로드 복구가 발생한 테스트 시나리오에서 동일 항목의 최종 저장 결과는 100% 한 번만 반영된다.
- **SC-006**: 자동 백업이 열 또는 전원 제약으로 중단된 경우, 재개 가능 run의 95% 이상이 다음 조건 충족 시 기존 상태를 보존한 채 다시 진행된다.
- **SC-006a**: 과열로 일시 중단된 자동 백업 run의 95% 이상이 온도 정상화 후 기존 상태를 보존한 채 다시 진행된다.
- **SC-007**: 자동 백업 실행 중 임시 준비 파일 누적 사용량은 100%의 경우 2GB를 초과하지 않아야 한다.

## Assumptions

- 자동 백업은 사용자가 명시적으로 활성화한 경우에만 동작한다.
- 자동 백업 v1은 로컬 네트워크 기반 Mac receiver 백업만 대상으로 한다.
- 자동 백업은 충전 중이 아니어도 실행될 수 있지만, 배터리 잔량이 20% 이상이어야 한다.
- 자동 백업은 Wi-Fi가 켜져 있을 때만 실행된다.
- 저전력 모드는 자동 백업 차단 조건으로 사용하지 않는다.
- 자동 백업용 임시 준비 파일 총 사용량은 2GB를 초과하지 않도록 제한한다.
- 실패 항목은 사용자가 원본을 삭제하지 않는 한 이후 자동 백업 run에서 계속 재평가 대상으로 남는다.
- 미완료 자동 백업 run 기록은 7일을 초과하면 정리 대상이 될 수 있다.
- 자동 백업은 iPhone Photos의 원본 파일을 변경하지 않고, 필요 시 별도 임시 준비 파일만 사용한다.
- 자동 백업 상태 표시는 기존 iOS/macOS 대시보드 구조를 유지한 채 필요한 상태와 사유를 추가하는 수준으로 제공된다.
- Mac receiver는 실행 중이며 네트워크에서 도달 가능해야 실제 업로드가 진행된다.
- 자동 백업 v1은 Mac 간 미완료 run handoff를 지원하지 않으며, receiver를 변경하면 새 receiver 기준 새 run만 시작한다.
